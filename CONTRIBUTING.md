# Contributing to AI Tinkerers Luxembourg 🇱🇺

Thank you for helping build an open, practical, and welcoming AI community in Luxembourg! Whether you are contributing code, tutorials, documentation, demos, or ideas, your participation matters.

This guide applies to contributions to the [Luxembourg AI Tinkerers `Main` repository](https://github.com/Luxembourg-AI-Tinkerers/Main). Individual projects may have additional instructions in their own repositories.

## Ways to contribute

- **Improve documentation:** Fix errors, clarify instructions, translate content, or suggest resources.
- **Share projects:** Propose demos, sample applications, open-source tools, or reproducible experiments.
- **Help others learn:** Add tutorials, examples, or links to useful learning materials.
- **Report problems:** Open an issue for broken links, bugs, or unclear information.
- **Review contributions:** Give constructive feedback on issues and pull requests.
- **Suggest activities:** Share ideas for technical sessions, workshops, and collaborations.

Contributors of all experience levels are welcome.

## Before you start

1. Read our [Code of Conduct](CODE_OF_CONDUCT.md).
2. Check existing issues and pull requests to avoid duplicating work.
3. For large changes or new initiatives, open an issue first to discuss the idea.
4. Check the target repository's README and existing style before making edits.

**Security issues:** Please do **not** disclose vulnerabilities, credentials, or sensitive data in public issues or pull requests. Follow our [Security Policy](SECURITY.md) instead.

## Contributing through GitHub

For a small documentation change, you can use GitHub's **Edit this file** action and propose the change directly.

For larger changes:

1. Fork the relevant repository (unless you already have write access).
2. Clone your fork and create a descriptive branch:

   ```bash
   git clone https://github.com/YOUR-USERNAME/.github.git
   cd .github
   git checkout -b docs/improve-community-guide
   ```

3. Make your changes, keeping them focused and easy to review.
4. Preview Markdown files and run any checks specified by the project.
5. Commit with a clear message:

   ```bash
   git add .
   git commit -m "docs: improve community contribution guide"
   git push -u origin docs/improve-community-guide
   ```

6. Open a pull request against the appropriate repository's default branch. Explain what changed, why it helps, and how you verified it.

Replace `YOUR-USERNAME` in the example with your GitHub username. For contributions to other organization repositories, use that project's repository name instead of `.github`.

## Pull request checklist

Before requesting review, please confirm:

- [ ] The change is relevant to the community or project.
- [ ] The description explains the purpose and impact.
- [ ] Documentation and examples are updated where needed.
- [ ] Links work and Markdown renders correctly.
- [ ] Applicable tests or project checks pass, or limitations are noted.
- [ ] No secrets, personal information, or proprietary materials are included.
- [ ] Any third-party assets or dependencies have compatible licensing and attribution.
- [ ] AI-assisted content or code has been reviewed for accuracy, security, and licensing, and significant AI assistance is disclosed in the pull request when relevant.

## Quality and collaboration guidelines

**Be practical and reproducible.** For AI examples, explain the setup, dependencies, expected behavior, and important limitations. Where feasible, include a minimal example and sample inputs that contain no sensitive data.

**Be responsible with AI.** Avoid publishing private datasets, API keys, copied proprietary models, or unlicensed content. State meaningful risks and limitations rather than presenting generated outputs as verified facts.

**Be respectful.** Offer specific, actionable feedback and assume good intent. Discussions and reviews must follow the [Code of Conduct](CODE_OF_CONDUCT.md).

**Be patient.** Reviews are handled by volunteers, and response times may vary. Maintainers may request revisions, suggest a different approach, or decline contributions that do not fit a project's scope.

## Licensing your contribution

By submitting a contribution, you confirm that you have the right to share it under the license of the **repository receiving the contribution**. For this `.github` repository, see [LICENSE](LICENSE). Other repositories may use different licenses; check each one before contributing.

## Questions and ideas

For general questions or proposals, open an issue in the [community `.github` repository](https://github.com/Luxembourg-AI-Tinkerers/.github/issues) if issues are enabled, or use the contact and community channels listed on the [AI Tinkerers Luxembourg website](https://luxembourg.aitinkerers.org/).
